## v1.0(v0.3) → v2.0(v0.4) 변경 요약

| 항목 | v1.0 (ClickUp) | v2.0 (Jira) |
|------|----------------|-------------|
| 업무 단위 | 단일 Task + task_type 분기 | **work_item 단일 테이블 + issue_type(Epic/Story/Task/Bug/Sub-task)** |
| 분류 축 | 업무영역(Area) 필수 | **프로젝트 필수** (영역 개념 폐기) |
| 담당자 | **필수** | **권장(미배정 허용)** — 막힘 방지·등록 마찰 최소화 |
| 강제 범위 | 영역 상속·상태 시작값 | **계층 정합성만 시스템 강제** (워크플로 순서 강제 금지) |
| 측정·마스터 | (없음) | **측정 추상화 + 마스터 데이터(하드코딩 금지)** |

> 핵심 컨셉 유지: **하나의 work_item 데이터, 여러 관점.** 백로그·보드·목록·타임라인·이슈·리스크·WBS는 work_item의 파생 뷰(별도 테이블 금지).

## 명명 규칙

- 규칙 ID 형식: `BIZ-[순번]` (예: BIZ-001)
- 우선순위: **High** = Phase 1 MVP 필수 | **Medium** = Phase 2 추가 | **Low** = Phase 3+

## 규칙 vs 정책 구분

- **규칙(여기 BIZ-xxx)** = 변하지 않는 핵심, **코드에 고정**:
  - "프로젝트 필수"(BIZ-001), "삭제는 소프트"(BIZ-009), "상태는 FSM 화이트리스트만"(BIZ-010), "계층 정합성"(BIZ-103), "이슈/리스크 = 파생 뷰"(BIZ-106)
- **정책(T1-4)** = 운영 중 조정 가능, **설정으로 관리**:
  - 지연 판단 기준(due_date 초과 + 제외 상태 집합), 장기 미변경 기준 일수, 리스크 감지 조건식, 워크플로 상태·전이 내용(BIZ-107의 데이터), 필드 스킴 on/off

> 경계 원칙: "무엇을 강제하는가"(예: 막힘 깃발엔 사유가 있어야 한다)는 규칙, "그 임계값/대상이 무엇인가"(예: 지연 = 며칠 초과, 어느 상태를 제외)는 정책.
