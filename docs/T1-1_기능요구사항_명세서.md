## v1.0(v0.3) → v2.0(v0.4) 변경 요약

| 항목 | v1.0 (ClickUp) | v2.0 (Jira) |
|------|----------------|-------------|
| 업무 단위 | 단일 Task + task_type 분기 | **work_item 단일 테이블 + issue_type(Epic/Story/Task/Bug/Sub-task) + parent_id/epic_id 계층** |
| 실행 모델 | 칸반 중심 | **Backlog → Sprint → Board** (개발형) / Kanban(운영형) |
| 측정 | (없음) | **측정 추상화(measure_unit 마스터 + target/current)** — Phase 1 포함 |
| 관리자 설정 | 고정 시드 | **마스터 데이터(측정단위·필드스킴·워크플로·업무유형) — 하드코딩 금지** |
| 검색·필터 | 통합목록 필터 | **기본필터/전문검색/퀵필터/저장필터** (기획서 §13.9) |

> 핵심 컨셉 유지: **하나의 work_item 데이터, 여러 관점**. 백로그·보드·목록·타임라인·이슈는 work_item의 파생 뷰(별도 테이블 금지).

## 기능 상세

### A. 인증/사용자

#### WMP-AUTH-001 | 로그인
- **모듈**: A. 인증/사용자 > A1. 인증
- **설명**: 내부 계정(이메일/비밀번호)으로 로그인하고 JWT를 발급한다.
- **입력**: 이메일, 비밀번호
- **출력**: Access Token + Refresh Token, 사용자 정보
- **제약조건**: 비활성 계정 로그인 불가. bp-common-lib `JwtTokenProvider` 확장.
- **우선순위**: High | **MVP**: Y

#### WMP-AUTH-002 | 로그아웃
- **모듈**: A. 인증/사용자 > A1. 인증
- **설명**: 현재 토큰을 무효화한다.
- **입력**: Access Token | **출력**: 성공 응답
- **우선순위**: High | **MVP**: Y

#### WMP-AUTH-003 | 내 정보 조회
- **모듈**: A. 인증/사용자 > A1. 인증
- **설명**: 로그인 사용자의 프로필·역할을 조회한다.
- **입력**: Access Token | **출력**: userId, 이름, 이메일, role, deptId
- **제약조건**: 🔒 인증 필요
- **우선순위**: High | **MVP**: Y

#### WMP-AUTH-004 | 사용자 초대 (이메일 인증번호)
- **모듈**: A. 인증/사용자 > A2. 사용자 관리
- **설명**: 관리자가 이메일·이름·역할·부서로 사용자를 **초대**한다. 초대 시 user 계정을 즉시 만들지 않고 `invitations` 레코드만 생성하며, 초대 대상의 이메일로 6자리 **인증번호(OTP)**를 발송한다. 초대받은 사람이 인증번호 입력 → 비밀번호 설정을 완료한 **그 시점에 user 계정이 생성**되고 초대가 ACCEPTED 처리된다. (직접 비밀번호를 지정하는 "초기 비밀번호" 방식 폐기 — CR-027)
- **입력**: 이메일, 이름, 역할, 부서 | **출력**: 생성된 초대(invitation) 요약(이메일·역할·만료시각, 인증번호는 미반환)
- **제약조건**: Owner/Admin만. 이메일 UNIQUE(이미 가입된 이메일·미만료 PENDING 초대 중복 거부). 인증번호 만료·시도횟수 정책은 POL-013 따름. 이메일 발송은 bp-notification 연동(WMP-AUTH-009).
- **우선순위**: High | **MVP**: Y

#### WMP-AUTH-005 | 사용자 목록/수정/비활성화
- **모듈**: A. 인증/사용자 > A2. 사용자 관리
- **설명**: 목록 조회, 역할·부서 수정, 비활성화(소프트 삭제).
- **입력**: 사용자 ID, 변경 필드 | **출력**: 변경 사용자
- **제약조건**: Owner/Admin만. 삭제는 비활성화로.
- **우선순위**: High | **MVP**: Y

#### WMP-AUTH-006 | 초대 수락 (인증번호 검증 + 비밀번호 설정)
- **모듈**: A. 인증/사용자 > A1. 인증
- **설명**: 초대 이메일로 받은 인증번호와 이메일로 본인을 확인하고, 비밀번호를 설정해 가입을 완료한다. 검증 성공 시 user 계정이 생성되고(이름·역할·부서는 초대값 승계) 초대는 ACCEPTED 처리된다. 가입 완료 후 곧바로 로그인할 수 있다.
- **입력**: 이메일, 인증번호(6자리), 새 비밀번호 | **출력**: 가입 완료(성공 응답, 선택적으로 JWT 즉시 발급)
- **제약조건**: 🔓 비인증(공개). 인증번호 만료/시도횟수 초과 시 거부(POL-013). 비밀번호 정책 POL-012. 이미 ACCEPTED/만료된 초대는 거부.
- **우선순위**: High | **MVP**: Y

#### WMP-AUTH-007 | 비밀번호 분실 재설정 (forgot, 인증번호)
- **모듈**: A. 인증/사용자 > A1. 인증
- **설명**: 로그인하지 못하는 사용자가 가입 이메일로 6자리 인증번호를 발급받아, 인증번호 검증 후 새 비밀번호를 설정한다.
- **입력**: (1단계) 이메일 → 인증번호 발송 / (2단계) 이메일, 인증번호, 새 비밀번호 | **출력**: 재설정 완료
- **제약조건**: 🔓 비인증(공개). **이메일 존재 여부를 응답으로 노출하지 않는다**(계정 열거 방지 — 미존재 이메일도 동일하게 성공 응답). 인증번호 만료/시도횟수 POL-013. 비활성 계정은 발송하지 않되 응답은 동일.
- **우선순위**: High | **MVP**: Y

#### WMP-AUTH-008 | 비밀번호 변경 (로그인 상태, 현재 PW + 인증번호 2차 인증)
- **모듈**: A. 인증/사용자 > A1. 인증
- **설명**: 로그인한 사용자가 비밀번호를 변경한다. 현재 비밀번호 검증 + 본인 이메일로 발송된 6자리 인증번호 검증을 모두 통과해야 새 비밀번호로 변경된다(2차 인증).
- **입력**: (1단계) 인증번호 발송 요청 / (2단계) 현재 비밀번호, 인증번호, 새 비밀번호 | **출력**: 변경 완료
- **제약조건**: 🔒 인증 필요. 현재 비밀번호 불일치 시 거부(INVALID_CREDENTIALS). 인증번호 정책 POL-013. 비밀번호 정책 POL-012. 새 비밀번호는 현재와 동일 불가.
- **우선순위**: High | **MVP**: Y

#### WMP-AUTH-009 | 인증번호 이메일 발송 (bp-notification 연동)
- **모듈**: A. 인증/사용자 > A1. 인증 (내부 연동)
- **설명**: 초대·분실재설정·변경 시 6자리 인증번호를 사내 알림 솔루션 bp-notification REST API(`POST /api/v1/messages/email`)로 발송한다. WorkMap은 bp-notification에 solutionCode `WMP`로 등록되어 발급받은 API Key(`X-API-Key`)로 호출하며, 용도별 이메일 템플릿(`WMP_INVITE_OTP`/`WMP_RESET_OTP`/`WMP_CHANGE_OTP`)에 인증번호·만료분을 variables로 전달한다.
- **입력**: 수신 이메일, 용도(INVITE/RESET/CHANGE), 인증번호, 만료분 | **출력**: 발송 결과(requestId)
- **제약조건**: 외부 호출 실패가 인증번호 발급 트랜잭션을 막지 않도록 발송은 best-effort 처리(실패 로깅). API Key·Base URL은 환경설정(`workmap.notification.*`)으로 주입. 인증번호 평문은 응답·로그에 남기지 않는다.
- **우선순위**: High | **MVP**: Y

### B. 워크스페이스/프로젝트

#### WMP-WS-001 | 워크스페이스 관리
- **모듈**: B > B1. 워크스페이스
- **설명**: 회사/큰 업무 공간(워크스페이스)을 생성·관리한다. 프로젝트의 상위 컨테이너이자 **멤버십 격리 경계**(CR-018). "사람을 모은 작업공간"(슬랙 워크스페이스 모델) — 사용자는 자신이 속한 WS만 진입·조회하고, WS 안에 다수 프로젝트가 귀속된다.
- **입력**: 이름, 설명 | **출력**: 워크스페이스
- **제약조건**: 전사 Owner/Admin만 생성(WS별 Admin은 두지 않음 — CR-018 결정). WS는 격리 경계이므로 비멤버는 그 WS의 프로젝트·업무·검색·대시보드 어디에도 접근 불가(BIZ-110).
- **우선순위**: High | **MVP**: Y

#### WMP-WS-002 | 프로젝트 생성(유형 프리셋)
- **모듈**: B > B2. 프로젝트
- **설명**: 프로젝트를 생성한다. 유형(개발형/운영형/계획형)을 고르면 기본 탭(뷰) 조합이 프리셋으로 켜진다(기획서 §7). 유형은 출발점이며 탭은 켜고 끌 수 있다.
- **설명(보강)**: 생성은 **다단계 마법사**(템플릿 선택→이름/키→설정 확인·수정→멤버/가시성). 각 단계는 템플릿 기본값을 미리 채우고 수정 가능(T3-3). "나중에 변경 가능".
- **입력**: 워크스페이스, 이름, **유형(template_id — project_template 마스터에서 선택)**, 기간(선택), 관련 솔루션(선택), **withSample(샘플 데이터로 시작 토글, 기본 false)**
- **출력**: 프로젝트 + 활성 탭 조합(템플릿 default_tabs/issue_type_codes/workflow 복사). withSample=true면 예시 work_item 시드 생성
- **제약조건**: Manager 이상. **유형은 enum이 아니라 project_template 마스터 행**(BIZ-107). DEV/OPS/PLAN은 Phase 1 시드 예시. 새 템플릿 추가는 전용 화면/API 없이 **DB 직접 수정/Flyway 시드 SQL**로 처리(빈도 낮은 운영 작업, 사용자 결정 2026-06-23). 템플릿은 탭조합+워크플로+업무유형 목록+필드스킴을 묶는다.
- **우선순위**: High | **MVP**: Y

#### WMP-WS-003 | 프로젝트 목록/요약
- **모듈**: B > B2. 프로젝트
- **설명**: 프로젝트 목록을 필터·검색하고, 프로젝트별 진행/지연/막힘을 요약한다.
- **입력**: 필터(워크스페이스/유형/상태), 페이지 | **출력**: 프로젝트 목록 + 요약 집계
- **제약조건**: 보관 항목 기본 제외. 페이징은 `PageResponse`.
- **우선순위**: High | **MVP**: Y

#### WMP-WS-004 | 프로젝트 수정/보관
- **모듈**: B > B2. 프로젝트
- **설명**: 프로젝트 정보 수정 및 보관(archived) 처리. 탭 조합 편집.
- **입력**: 프로젝트 ID, 변경 필드 | **출력**: 변경 프로젝트
- **제약조건**: 보관은 소프트 처리.
- **우선순위**: Medium | **MVP**: N

#### WMP-WS-005 | 프로젝트 멤버 초대/관리
- **모듈**: B > B3. 멤버
- **설명**: 워크스페이스/프로젝트에 멤버를 추가·역할 부여·제거한다. @멘션·담당자 지정의 전제(기획서 §13.5).
- **입력**: 프로젝트 ID, 사용자 ID, 역할 | **출력**: 멤버 목록
- **제약조건**: Manager 이상. 멤버만 담당자·보고자·멘션 대상 가능.
- **우선순위**: High | **MVP**: Y

#### WMP-WS-006 | 프로젝트 가시성(공개/비공개)
- **모듈**: B > B3. 멤버
- **설명**: 프로젝트를 공개(워크스페이스 전체) 또는 비공개(멤버만)로 설정한다. "누가 무엇을 보나"의 기본축(기획서 §13.5).
- **입력**: 프로젝트 ID, 가시성(PUBLIC/PRIVATE) | **출력**: 변경 프로젝트
- **제약조건**: 비공개 프로젝트는 멤버만 조회/검색에 노출. **단 이 가시성은 WS 멤버십(WMP-WS-007) 안에서의 2차 경계** — PUBLIC=그 WS 전체 멤버, PRIVATE=프로젝트 멤버만(BIZ-108, CR-018). 이슈수준 보안은 Phase 3.
- **우선순위**: High | **MVP**: Y

#### WMP-WS-007 | 워크스페이스 멤버 초대/관리 (CR-018 신설)
- **모듈**: B > B1. 워크스페이스
- **설명**: 워크스페이스에 멤버를 추가·제거한다. **WS 멤버십이 1차 격리 경계** — 누가 어느 WS에 속하는지를 기록하며, 이것이 프로젝트·업무·검색·대시보드 접근의 전제(BIZ-110). 기존 WMP-WS-005(프로젝트 멤버)와 별개 계층: WS멤버 → 그 안에서 프로젝트멤버.
- **입력**: 워크스페이스 ID, 사용자 ID | **출력**: WS 멤버 목록
- **제약조건**: 전사 Owner/Admin만 WS 멤버 관리(WS별 Admin 없음 — CR-018). WS 멤버가 아니면 그 WS의 어떤 화면에도 진입 불가. WS 멤버여야 그 안 프로젝트의 멤버가 될 수 있다.
- **우선순위**: High | **MVP**: Y

#### WMP-WS-008 | 워크스페이스 선택/전환 (CR-018 신설)
- **모듈**: B > B1. 워크스페이스
- **설명**: 로그인 후 작업할 워크스페이스를 선택하고, 이후 그 WS 컨텍스트로 진입한다. 선택은 기억되어 다음 로그인 시 자동 진입하며, 사용자는 언제든 다른 WS로 전환할 수 있다(슬랙식). 선택된 WS가 홈·받은함·검색·프로젝트목록의 컨텍스트가 된다.
- **입력**: (자신이 속한 WS 목록) → 선택한 WS ID | **출력**: 선택된 WS 컨텍스트
- **제약조건**: 선택 가능 목록 = 자신이 속한 WS만(WMP-WS-007). 선택 기억은 클라이언트(localStorage) 저장하되 **진입 시 서버가 멤버십 재검증**(탈퇴한 WS면 차단→선택 화면). 속한 WS가 0개면 안내 화면, 1개면 자동 진입.
- **우선순위**: High | **MVP**: Y

### C. 업무 항목 (Work Item)

> 핵심 단위. Epic/Story/Task/Bug/Sub-task는 work_item **단일 테이블** + issue_type + parent_id/epic_id 계층(기획서 §14, §15.1-5). 백로그·보드·목록·타임라인·이슈는 모두 work_item의 파생 뷰.

#### WMP-WI-001 | 업무 항목 생성(만들기 모달)
- **모듈**: C > C1. CRUD
- **설명**: 만들기 모달로 업무 항목을 등록한다. "만들기는 가볍게" — 공통(스페이스·유형·상태·요약·설명) + 선택(담당자/우선순위/라벨/Epic)만. 유형별 풍부한 필드는 상세에서 채움(기획서 §9.4, §8.3a).
- **입력**: 프로젝트(필수), issue_type(필수), 상태(초기), 요약(필수), 설명, +선택 필드
- **출력**: 생성된 work_item (key 자동 발급: 프로젝트키-순번)
- **제약조건**: BIZ-002(담당자 권장이나 미배정 허용 — 막힘 방지). BIZ-101(생성 시 상태=워크플로 시작상태). 계층 정합성(BIZ-103) 검증.
- **우선순위**: High | **MVP**: Y

#### WMP-WI-002 | 업무 항목 수정(인라인 편집)
- **모듈**: C > C1. CRUD
- **설명**: work_item 필드를 수정한다. 제목·필드 인라인 편집 포함. 상태 변경은 WMP-WI-007로 분리.
- **입력**: work_item ID, 변경 필드 | **출력**: 변경 work_item
- **제약조건**: 변경 시 activity_log 기록(WMP-WI-011).
- **우선순위**: High | **MVP**: Y

#### WMP-WI-003 | 업무 항목 삭제(소프트)
- **모듈**: C > C1. CRUD
- **설명**: work_item을 소프트 삭제(deleted_at)한다.
- **입력**: work_item ID | **출력**: 성공 응답
- **제약조건**: BIZ-009(소프트 삭제). 하위 항목 존재 시 함께 처리.
- **우선순위**: High | **MVP**: Y

#### WMP-WI-004 | 업무 항목 상세 조회(유형별 분기)
- **모듈**: C > C1. CRUD
- **설명**: work_item 전체 필드 + 하위 작업 + 연결된 항목 + 관련 문서 + 댓글 + 활동이력을 조회한다. 유형별 본문 분기(Epic=하위묶음+진행률, Story=인수조건, Task=체크리스트, Bug=재현·심각도, Sub-task=부모링크)(기획서 §9.3).
- **입력**: work_item ID | **출력**: 상세 + 하위 + 연결 + 댓글 + 이력
- **제약조건**: 비공개 프로젝트는 멤버 권한 확인(WMP-WS-006).
- **우선순위**: High | **MVP**: Y

#### WMP-WI-005 | 하위 작업(Sub-task) 생성
- **모듈**: C > C2. 계층
- **설명**: parent_id를 가진 Sub-task를 만든다. Sub-task는 Story/Task/Bug 누구의 자식도 가능(기획서 §3.1).
- **입력**: 부모 work_item ID + 생성 필드 | **출력**: Sub-task
- **제약조건**: BIZ-103(계층 정합성: Sub-task는 부모 필수, Epic은 Sub-task 부모 불가, depth≤2). 순환 금지.
- **우선순위**: High | **MVP**: Y

#### WMP-WI-006 | 담당자/보고자 지정·변경
- **모듈**: C > C3. 담당
- **설명**: 담당자(assignee)·보고자(reporter)를 인라인 변경한다.
- **입력**: work_item ID, assigneeId, reporterId | **출력**: 변경 work_item
- **제약조건**: 담당자·보고자는 프로젝트 멤버만(WMP-WS-005). 배정 시 알림 발행(WMP-NOTI-002).
- **우선순위**: High | **MVP**: Y

#### WMP-WI-007 | 상태 전이(FSM 화이트리스트)
- **모듈**: C > C4. 상태
- **설명**: 상태를 전이한다. 워크플로(유형/프로젝트별) 화이트리스트만 허용(기획서 §12).
- **입력**: work_item ID, 다음 상태 | **출력**: 변경 work_item
- **제약조건**: BIZ-010(FSM 화이트리스트). BIZ-005(BLOCKED 전이 시 차단 사유 필수). BIZ-006(DONE 전이 시 completed_at 자동).
- **우선순위**: High | **MVP**: Y

#### WMP-WI-008 | 우선순위/기한/라벨 설정
- **모듈**: C > C1. CRUD
- **설명**: 우선순위, 시작일/기한, 라벨을 설정한다.
- **입력**: work_item ID, priority, start_date, due_date, labels[] | **출력**: 변경 work_item
- **제약조건**: start_date ≤ due_date(BIZ-007).
- **우선순위**: High | **MVP**: Y

#### WMP-WI-009 | 댓글 + @멘션
- **모듈**: C > C5. 협업
- **설명**: work_item에 댓글을 작성하고 @멘션한다.
- **입력**: work_item ID, 내용, 멘션 사용자[] | **출력**: 생성 댓글
- **제약조건**: 멘션 대상은 프로젝트 멤버. 멘션 시 알림 발행(WMP-NOTI-002).
- **우선순위**: High | **MVP**: Y

#### WMP-WI-010 | 진행률 자동 집계(Epic/Story)
- **모듈**: C > C2. 계층
- **설명**: 하위 항목/체크리스트 완료 비율로 상위(Epic/Story) 진행률을 자동 집계한다(기획서 §8.4).
- **입력**: work_item ID(상위) | **출력**: progress(0~100)
- **제약조건**: BIZ-008(하위 있으면 자동). 누적값은 자동(§8.4 원칙).
- **우선순위**: High | **MVP**: Y

#### WMP-WI-011 | 활동/변경 이력
- **모듈**: C > C6. 이력
- **설명**: 상태·담당자·필드 변경을 activity_log에 기록하고 상세에 타임라인으로 표시한다.
- **입력**: 변경 이벤트(자동) | **출력**: 활동 이력 목록
- **제약조건**: 상태 전이/담당자 변경은 반드시 기록.
- **우선순위**: High | **MVP**: Y

#### WMP-WI-012 | 첨부파일
- **모듈**: C > C5. 협업
- **설명**: work_item 상세에 파일을 첨부한다.
- **입력**: work_item ID, 파일 | **출력**: 첨부 목록
- **제약조건**: 저장소는 로컬/오브젝트(구현 시 결정). 메타는 attachment 테이블.
- **우선순위**: High | **MVP**: Y

#### WMP-WI-013 | 연결된 업무 항목(이슈 링크)
- **모듈**: C > C2. 계층
- **설명**: 계층과 무관한 링크(blocks/blocked by/relates to/duplicates)를 양방향 자동으로 맺는다. 하위 작업과 별개 섹션(기획서 §9.3, §13.1).
- **입력**: work_item ID, 대상 ID, 링크 유형 | **출력**: 양방향 링크
- **제약조건**: A blocks B → B에 blocked by 자동. 자기참조 금지.
- **우선순위**: Medium | **MVP**: N

#### WMP-WI-014 | 유형 전환(Move/Convert)
- **모듈**: C > C1. CRUD
- **설명**: issue_type을 변경(Task↔Story)하거나 Sub-task↔Story 승격/강등한다. 안개 걷기 재분류에 필수(기획서 §13.1).
- **입력**: work_item ID, 새 issue_type | **출력**: 변경 work_item
- **제약조건**: 계층 정합성 재검증(BIZ-103). 유형 변경 시 미사용 유형고유 필드는 보존(비표시).
- **우선순위**: High | **MVP**: Y

#### WMP-WI-015 | 벌크 편집(일괄 변경)
- **모듈**: C > C1. CRUD
- **설명**: 목록/검색결과에서 여러 항목 선택 → 상태·담당자·스프린트·라벨·우선순위 일괄 변경. 안개 걷기 대량 재분류의 핵심(기획서 §13.1, §13.8).
- **입력**: work_item ID[], 변경 필드 | **출력**: 변경 건수
- **제약조건**: 상태 일괄 변경 시 각 항목 FSM 검증(BIZ-010). 실패 항목 분리 보고.
- **우선순위**: High | **MVP**: Y

#### WMP-WI-016 | 목표·실적 측정(측정 추상화)
- **모듈**: C > C7. 측정
- **설명**: work_item에 측정단위·목표값·현재값을 두어 진행을 정량/정성으로 표현한다(기획서 §8.5/8.6). 개발=정성(완료여부), 운영=정량(건수/금액/%)을 한 모델로.
- **입력**: work_item ID, measure_unit_id, target_value, current_value | **출력**: progress 자동 계산
- **제약조건**: progress = 현재÷목표(정량) 또는 상태 기반(정성). 측정단위는 measure_unit 마스터(WMP-ADM-001).
- **우선순위**: High | **MVP**: Y

  - 스프린트 시작/완료(SPRINT_STARTED/COMPLETED → 프로젝트 멤버) · 승인 요청/처리(APPROVAL_REQUESTED/DECIDED) — *신규 리스너*
- **입력**: 도메인 이벤트(T1-6 계약) | **출력**: notification 레코드 + (설정 ON 시) 외부 전달
- **제약조건**: 이벤트 계약(T1-6) 준수. 행동 필요 시에만 발행. 모든 발행은 `NotificationDispatcher` 단일 진입점 경유(인앱 기록 + 설정 확인 + 외부 fan-out).
- **우선순위**: High | **MVP**: Y

#### WMP-NOTI-003 | 알림 수신 설정 (CR-028)
- **모듈**: I > I3. 수신 설정
- **설명**: 사용자별로 알림 종류(ASSIGNED/BLOCKED/.../OVERDUE) × 전달 채널(인앱/이메일/푸시)을 on/off(기획서 §13.7.1, POL-009). 미설정 종류는 **기본값(인앱 ON·이메일 OFF·푸시 OFF)** 적용(sparse 저장).
- **입력**: Access Token + 설정 변경 | **출력**: 설정 목록 / 갱신 결과
- **제약조건**: 인앱 받은함 기록 자체는 끄지 못한다(원장 보존). in_app 토글은 받은함 표시/배지 노출 범위만 제어. POL-009 전역 트리거 on/off가 OFF면 발행 자체를 막아 사용자 설정보다 우선.
- **우선순위**: High | **MVP**: Y

#### WMP-NOTI-004 | 외부 전달 채널(bp-notification 연동) (CR-028)
- **모듈**: I > I4. 외부 전달
- **설명**: 인앱 알림을 사내 알림 솔루션 bp-notification REST API로 이메일(`POST /api/v1/messages/email`)·푸시(`POST /api/v1/messages/push`) 전달. 종류별 템플릿(`WMP_NOTI_ASSIGNED` 등)에 업무명·프로젝트·링크를 variables로 전달.
- **입력**: 인앱 알림 + 수신자 설정/연락처 | **출력**: bp-notification 발송 요청
- **제약조건**: **best-effort** — bp-notification 장애/오류가 WorkMap 트랜잭션·인앱 기록을 막지 않는다(`@Async` + try/catch). 인앱 기록은 이미 커밋된 뒤 발송. 푸시는 FCM 토큰 등록 사용자만 대상.
- **우선순위**: High | **MVP**: Y

#### WMP-NOTI-005 | 마감 알림 스케줄러 (CR-028)
- **모듈**: I > I2. 트리거(스케줄)
- **설명**: 매일 1회(오전) 미완료 work_item의 due_date를 스캔하여 마감임박(`due_date - today ≤ notify.due-soon-days`, POL-009 기본 1일)·마감초과(`due_date < today`, POL-002) 항목에 알림 발행. 이벤트=WorkItemDueApproaching/WorkItemOverdue(T1-6).
- **입력**: `@Scheduled` cron | **출력**: 해당 담당자 알림
- **제약조건**: 같은 work_item·같은 타입·같은 날 **1회만**(중복 방지). 완료/취소 상태 제외(POL-002 제외 집합). 담당자 없으면 스킵.
- **우선순위**: High | **MVP**: Y

### J. 모바일 앱 (Mobile App — CR-029)

> WorkMap을 iOS/Android 네이티브 앱으로 제공한다. 현재 React/Vite FE를 **Capacitor로 래핑**(웹뷰 + 네이티브 브리지)하여 코드베이스를 재활용한다(React Native 신규 작성 안 함). 참고 구현: `dev-labs/bp-issues-front`(Capacitor 8 + push-notifications, 동일 조직 패턴).
> **CR-029 범위**: WMP-APP-001(앱 셸)만 **구현**. 002~004(푸시/카메라/음성)는 **설계만 선기재**, 구현은 후속 CR(030+)에서 착수.

#### WMP-APP-001 | 네이티브 앱 셸 (Capacitor 래핑)
- **모듈**: J > J1. 앱 셸
- **설명**: 현재 Vite 빌드 산출물(`frontend/dist`)을 Capacitor `webDir`로 삼아 iOS/Android 네이티브 셸에 탑재. 앱 실행 시 운영 BE(`http://59.8.160.12:8186`)에 절대 URL로 접속(앱은 dev 프록시가 없음). SplashScreen 표시.
- **입력**: 없음(앱 기동) | **출력**: 네이티브 셸에서 WorkMap 웹앱 렌더링
- **제약조건**: appId=`com.therecommerce.workmap`, appName=`WorkMap`. `server.allowNavigation`에 운영 호스트(`59.8.160.12`) 명시. BE 변경 0(기존 API 그대로). 모바일 폭에서 LNB가 ds-ui AdminShell 동작에 맞게 접히는지 별도 점검(부족 시 후속 보강). **푸시/카메라/음성 플러그인은 이 단계에서 추가하지 않는다.**
- **우선순위**: Medium(Phase 2+ 앱 제공) | **MVP**: N

#### WMP-APP-002 | 모바일 푸시 알림 (설계만, 구현=후속 CR)
- **모듈**: J > J2. 푸시
- **설명**: `@capacitor/push-notifications`로 FCM 토큰을 발급받아 **기존 BE `POST /api/v1/fcm/token`**(CR-028, 실측 확인)에 등록. 포그라운드 수신=ds-ui Toast, 백그라운드 탭=알림 data(workItemId 등)로 해당 화면 딥링크 이동. 발송은 CR-028 `BpNotificationGateway`(bp-notification 푸시)가 이미 담당.
- **입력**: 푸시 권한 + FCM 토큰 | **출력**: BE 토큰 등록 / 알림 수신·탭 라우팅
- **제약조건**: `Capacitor.isNativePlatform()` 가드(웹에서 미동작). 중복 토큰 등록 방지. **선행 인프라**: Firebase 프로젝트·iOS APNs 키·`google-services.json`/`GoogleService-Info.plist` 필요(현재 미보유 — CR-029에서 미착수, 후속 CR에서 준비). FE `registerFcmToken`/`deleteFcmToken`는 이미 존재(미배선) — Capacitor 도입 시 `usePushNotifications` 훅에서 호출.
- **우선순위**: Medium | **MVP**: N

#### WMP-APP-003 | 카메라 촬영/첨부 (설계만, 구현=후속 CR)
- **모듈**: J > J3. 카메라
- **설명**: `@capacitor/camera`로 촬영/갤러리 선택 → 기존 파일 업로드(`POST /api/v1/files/upload`, CR-024)로 전송. 업무 첨부(WMP-WI-012)·리치에디터 이미지 삽입에 연결.
- **입력**: 카메라 권한 + 촬영 이미지 | **출력**: 업로드 URL → 첨부/본문 삽입
- **제약조건**: 네이티브 가드. 기존 FileStorage 화이트리스트(image 4종, 10MB)·서빙 경로 재사용(BE 변경 0). 웹에서는 기존 `<input>` 기반 업로드 유지.
- **우선순위**: Medium | **MVP**: N

#### WMP-APP-004 | 음성 녹음/입력 (설계만, 구현=후속 CR)
- **모듈**: J > J4. 음성
- **설명**: 음성 녹음(첨부/메모) 및 음성 입력(받아쓰기). 녹음=커뮤니티 Capacitor 플러그인(예: `capacitor-voice-recorder`) → 파일 업로드. 음성인식(STT)은 OS 네이티브 STT 플러그인 또는 BE STT 연동(범위 미정).
- **입력**: 마이크 권한 + 음성 | **출력**: 음성 파일 첨부 / 텍스트 변환 입력
- **제약조건**: 네이티브 가드. STT 정확도·언어(한국어)·온/오프라인 여부는 후속 CR 설계에서 확정. iOS/Android STT 차이 점검 필요.
- **우선순위**: Low | **MVP**: N
