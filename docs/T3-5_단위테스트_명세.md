## 레이어별 테스트 범위

| 레이어 | 필수 여부 | 대상 | 패턴 |
|--------|----------|------|------|
| Service | **필수** | 비즈니스 로직, FSM 전이(허용+금지), 계층 정합성, 측정/진행률, 이벤트 발행 | `{Name}ServiceTest.java` |
| Mapper | 선택 | 복잡 쿼리(통합 목록 필터·지연 집계 복합 인덱스)만 | `{Name}MapperTest.java` |
| Controller | 조건부 필수 | 생성(POST) Happy Path는 엔티티별 최소 1건 필수 | `{Name}ControllerTest.java` |
| Store/Hook(FE) | **필수** | 보드/백로그 드래그 낙관적 업데이트·롤백, 인증/필터 store | `*.test.ts` |
| Component(FE) | 선택 | 칸반 드래그 등 주요 인터랙션 | `*.test.tsx` |

### 모킹/시간 전략
- **외부 API**: 전부 Mock.
- **DB**: 테스트용 PostgreSQL(Testcontainers) 또는 Mapper Mock.
- **이벤트**: ApplicationEvent 발행 검증(Mock 리스너 / `ApplicationEventPublisher` Mock — 발행 여부 + 페이로드 필드).
- **시간 의존(지연·장기 미변경·completed_at)**: Clock Mock.
- **FE API**: MSW로 응답 시뮬레이션(성공/4xx 롤백).

### 테스트 이름 규칙
- "상황_행동_기대결과" (예: `Sub태스크_부모없이생성_거부됨`, `BLOCKED전이_사유없음_거부됨`).
- FSM 전이: **허용 + 금지** 모두 검증. 이벤트: **발행 여부 + 페이로드** 검증.
