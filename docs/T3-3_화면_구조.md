## 전역 네비게이션 (기획서 §9.1 — 확정)

**글로벌 LNB 1개 + 프로젝트 본문 상단 가로 탭(Jira식).** 좌측 2패널 아님(그건 ClickUp/Linear풍).

### 글로벌 LNB (좌측 1개, 전 화면 공통) — CR-018 WS 컨텍스트 반영

WorkMap은 **3층 IA**(전역 / 워크스페이스 / 프로젝트). WS=슬랙식 작업공간(사람을 모은 격리 멤버십 경계, BIZ-112). LNB는 **선택된 WS 컨텍스트** 안에서 그 WS의 메뉴·프로젝트를 보여준다.

```
[글로벌 LNB]
  ┌────────────────┐
  │ [WMS 1.0 ▾]    │  ← WS 스위처(맨 위 고정). 내가 속한 WS만(WMP-WS-008). 잘 안 바꿈
  └────────────────┘
  회사홈 · 받은함 · 검색       ← 선택된 WS 컨텍스트(전역 화면이지만 WS로 스코프)
  ── 프로젝트 ──              ← 선택된 WS의 프로젝트만 나열(상시, 활성 하이라이트)
    운영 프로젝트   ◀ 활성
    개발 프로젝트
    마이그레이션
  보관함 · 설정(전역)
```

- **LNB 표현 = ⓐ 확정(CR-018)**: WS 스위처 + 그 WS의 **프로젝트 목록 상시 나열 + 진입 시 활성 하이라이트.** 프로젝트는 LNB에 늘어나는 구조. 프로젝트 클릭 시 LNB는 **그대로 유지**(전환식 ⓑ/ⓒ는 "써보고 결정" 보류 — 사용자는 프로젝트를 자주 오가므로 목록 상시 노출이 전환에 유리).
- 프로젝트 내부 뷰 전환(요약/보드/…)은 LNB가 아니라 **본문 상단 가로 탭**으로 한다(아래 §). 즉 "한 단계 들어옴"은 본문 상단 브레드크럼+탭으로 표현하고, LNB는 프로젝트 간 이동을 담당.
- **WS 격리**: 비멤버는 그 WS 자체가 스위처에 안 보이고, 직접 URL 진입해도 서버 가드가 차단(BIZ-112). 회사홈·받은함·검색도 선택된 WS(및 내 멤버 WS) 범위.
- 헤더 우측 고정 액션: `[만들기]` 버튼(전역 만들기 모달 — 현재 선택된 WS·프로젝트 컨텍스트 프리셋), 검색, 알림(받은함).
- `설정`(admin 마스터 6종)은 **전역**(WS별로 안 쪼갬, CR-018). 측정단위·워크플로·업무유형은 조직 표준(BIZ-107/010).

### 프로젝트 상단 가로 탭 (Jira식, `+`로 추가/제거)

```
프로젝트 / 반품구조대                          ← 브레드크럼
반품구조대                       [멤버] [⋯]    ← 제목 + 액션
[요약][목록][보드][백로그][캘린더][타임라인][승인][보고서][+]
```

- 탭은 **고정이 아님** — `+`로 켜고 끈다. 유형 프리셋(§7)이 기본 조합을 정하고 사용자가 편집.
- **현재 구현된 탭 풀 = 8종**(route-paths `ProjectTab`과 1:1): 요약(summary)·목록(list)·보드(board)·백로그(backlog)·타임라인(timeline)·캘린더(calendar)·승인(approvals)·보고서(reports). (릴리스·문서·양식·목표는 화면 미구현 — 추후 항목별 개발 시 풀에 추가.)
- 유형별 기본 탭 프리셋(실존 8탭 기준, BE 시드 = FE 상수 일치 — CR-019 정합):
  - **개발형(DEV)**: 요약 · 백로그 · 보드 · 타임라인 · 보고서
  - **운영형(OPS)**: 요약 · 보드 · 목록 · 캘린더 · 승인 · 보고서
  - **계획형(PLAN)**: 요약 · 타임라인 · 보고서
  - **기본형(DEFAULT, CR-019)**: 8탭 전부(Jira "빈 스페이스" 대응 — 다 켜고 생성, 불필요 탭은 `[+]`/설정에서 끔)
- 탭 조합 편집(P2 구현):
  - **헤더 가로탭 옆 `[+]`**: 안 켜진 탭을 그 자리에서 빠르게 추가(켜기). 클릭 시 미노출 탭 메뉴 → 선택 시 `PATCH /projects/{id}` activeTabs에 추가(요약은 항상 노출, 끄기 불가).
  - **각 탭 = `아이콘 + 라벨`(CR-020)**: 탭 코드별 lucide 아이콘(요약=LayoutDashboard·목록=List·보드=Columns3·백로그=ListTodo·타임라인=GanttChart·캘린더=Calendar·승인=CheckCircle·보고서=BarChart). 코드가 안정적 키라 FE 매핑(tab_def.icon에 코드 보관, BE 무변경).
  - **드래그&드롭 순서 이동(CR-020)**: 탭을 드래그해 위치 변경(dnd-kit, 백로그와 동일 패턴). drop 시 재정렬된 activeTabs를 `PATCH /projects/{id}`로 저장. summary는 드래그 비활성(맨 앞 고정). 메뉴의 좌/우 이동은 보조로 유지(정밀·접근성).
  - **각 탭 호버 `…` 메뉴(Jira식, CR-020)**: 호버 시 우측에 `…` 버튼 노출 → 드롭다운 메뉴(Jira와 동일 구성·순서):
    - **기본값으로 설정** → `PATCH /projects/{id}` `defaultTab`. 진입 시 첫 화면이 됨.
    - **이름 바꾸기** → 인라인 입력 또는 작은 다이얼로그 → `PUT /projects/{id}/tabs/{code}/label`. 프로젝트별 커스텀명(되돌리기=DELETE, 기본값 폴백).
    - (구분선)
    - **탭을 왼쪽으로 이동 / 오른쪽으로 이동** → `PATCH /projects/{id}` activeTabs 순서 변경.
    - (구분선)
    - **제거** → `PATCH /projects/{id}` activeTabs에서 제거.
    - **요약(summary)은 제거·이동·기본해제 불가**(서버 가드 WMP-7808) — 메뉴에서 해당 항목 비활성.
  - **프로젝트 설정 다이얼로그(WMP-WS-004)**: 8탭 체크박스로 일괄 on/off.
  - 모든 진입점이 `PATCH /projects/{id}`(activeTabs/defaultTab) 또는 `/tabs/{code}/label`을 갱신하고 ProjectLayout이 `activeTabs` 우선 렌더(없으면 프리셋 폴백). **라벨은 `GET /projects/{id}/tabs`의 폴백 적용 표시명 사용**(코드 상수 `PROJECT_TAB_LABEL` 의존 제거 — tab_def DB가 정본).

## 페이지별 주요 영역

각 영역마다 표시/입력 데이터 + 연결 API를 명시한다.

### 로그인 (`/login`)
- **입력**: 이메일, 비밀번호
- **동작**: 제출 → 토큰 저장(Zustand) → `/` 리다이렉트. 실패 시 에러.
- API: `POST /auth/login`, `GET /auth/me`

### 회사 홈 (`/`) — 막힘 중심 대시보드 (§9.2)
작은 조직은 진행률보다 **막힌 것**을 본다. 다음 묶음을 상단에 크게.
- **막힌 업무**: BLOCKED 항목 + blockReason — `GET /dashboard/blocked`
- **지연 업무**: 기한 초과 미완료(POL-002) — `GET /dashboard/delayed`
- **미배정 업무**: 담당자 없음 — `GET /dashboard/unassigned`
- **검토 정체 / 심각 Bug / 현장검증 대기 / 운영반영 대기**: 지표 카드 — `GET /dashboard/metrics`
- 각 카드 클릭 → 해당 조건의 검색 결과(`/search`) 또는 목록으로 이동.
- 집계는 가시성(BIZ-108) 반영 — 볼 수 있는 프로젝트만.

### 받은함 (`/inbox`)
- **목록**: 내게 온 알림·멘션·배정·상태변경 통합. 읽음/안읽음 토글.
- 항목 클릭 → 해당 업무 상세.
- API: `GET /inbox`, `GET /notifications`, `PATCH /notifications/{id}/read`

### 검색 결과 (`/search`) (§13.9)
- **검색 바**: 제목·설명·댓글 전체 텍스트 검색.
- **필터 패널**: 유형·상태·담당자·우선순위·라벨·스프린트·Epic·기한·막힘여부 다중 선택.
- **퀵필터**: 내 항목 / 최근 업데이트 / 막힌 것 / 미배정 (토글).
- **결과 목록**: 표 형태, 행 클릭 → 업무 상세. (저장된 필터·공유 필터·JQL류는 P2~P3)
- API: `GET /work-items` (검색·필터·정렬·페이징·퀵필터 파라미터)

### 프로젝트 목록 (`/projects`)
- **필터**: 워크스페이스 · 유형(개발/운영/계획) · 상태 (보관 제외).
- **표/카드**: 이름 · 유형 · 진행률 · 지연/막힘 수, 행 클릭 → 프로젝트 요약.
- **액션**: 프로젝트 생성 → **생성 마법사**(아래) 진입.
- API: `GET /projects`, `POST /projects`

### 프로젝트 생성 마법사 (`/projects/new` — 다단계, Jira식)
> 모달 한 방이 아니라 **다단계 마법사**. 각 단계는 선택한 템플릿(project_template)의 기본값을 미리 채우고 사용자가 확인·수정한다(캡처 4단계 화면 = 아래 3단계 "설정 확인"에 해당). 좌상단 "N단계", 우하단 "다음/완료".

| 단계 | 내용 | 데이터 소스 |
|------|------|------------|
| 1. 템플릿 선택 | 시스템 시드 + 커스텀 템플릿 카드에서 선택(개발형/운영형/계획형 등) | project_template 마스터 |
| 2. 이름·키 | 프로젝트명, key(접두어), 워크스페이스, 기간(선택) | — |
| 3. 설정 확인·수정 | 템플릿이 미리 채운 **① 업무 유형(issue_type_codes) ② 상태(워크플로) ③ 보기(default_tabs)** 를 보여주고 펼쳐서 수정 가능. **"샘플 업무 항목으로 시작" 토글** | project_template + workflow 마스터 |
| 4. 멤버·가시성 | 멤버 초대(선택), 공개/비공개 | — |

- **각 항목은 "나중에 변경 가능"** 안내(캡처 문구와 동일). 마법사에서 수정한 값은 프로젝트로 복사(active_tabs/workflow_id/노출 유형), 이후 프로젝트 설정에서 재편집(WMP-WS-004).
- **샘플 데이터로 시작(토글)**: ON이면 생성 직후 템플릿에 맞는 **예시 work_item 시드 생성**(안개 걷기 전 학습/체험용). OFF면 빈 프로젝트. 기본 OFF.
- 완료 → `POST /projects`(template_id + 수정된 설정 + withSample 플래그) → 프로젝트 요약으로 이동.
- 자체 composite: **ProjectCreateWizard**(단계 스텝퍼).

### 프로젝트 요약 (`/projects/:key/summary`)
- **헤더**: 브레드크럼 · 프로젝트명 · 멤버 · 가로 탭.
- **요약 영역**: 전체/완료/지연/막힘 수, 진행률 바.
- **지연·막힘 목록**: 우선 노출.
- API: `GET /projects/{id}/summary`, `GET /projects/{id}/members`

### 백로그 (`/projects/:key/backlog`) (§6.1)
Jira 백로그 화면 그대로. 한 화면에 다중 스프린트 + 백로그 영역 공존.
- **상단 도구**: 백로그 검색 · 담당자 · 필터 · [차트][설정].
- **스프린트 영역(여러 개)**: 각 스프린트 헤더 = 이름 · 기간 · 항목 수 · 상태별 카운트(To Do/진행/완료) · 추정치 합 · 접기 · 액션 버튼(`[스프린트 시작]`/`[스프린트 완료]`, 앞 스프린트 진행 중이면 시작 회색).
- **Epic 펼침 트리**: 스프린트/백로그 내 항목을 Epic 그룹으로 묶어 펼침.
- **백로그 영역**: 미계획 항목 + `[스프린트 만들기]`.
- **인라인 생성**: 각 영역 `+ 만들기`로 모달 없이 행 추가.
- **드래그앤드롭**: 항목을 스프린트↔백로그 이동, 바닥글 끌어 범위 조정.
- **행 인라인 편집**: 상태(할일▾)·우선순위·담당자 행에서 즉시 변경.
- API: `GET /projects/{id}/backlog`, `GET·POST /projects/{id}/sprints`, `POST /sprints/{id}/start`, `POST /sprints/{id}/complete`, `PATCH /work-items/{id}/sprint`, `POST /work-items`(인라인 생성)

### 보드 (`/projects/:key/board`)
- **컬럼**: 워크플로 상태별(스크럼=현재 스프린트 범위 / 운영=칸반 전체). 컬럼별 카드 수.
- **카드**: 제목 · 담당자 · 우선순위 · 기한(지연 강조) · 막힘 표시. 인라인 카드 생성(컬럼 빈 줄 입력).
- **드래그로 상태 변경**: 낙관적 업데이트 + 서버 권위 롤백(T1-5 UI FSM). **BLOCKED 드롭 시 차단 사유 모달 먼저**(BIZ-005).
- **막힘 컬럼/배지**: 막힌 카드 구분.
- API: `GET /projects/{id}/board`, `PATCH /work-items/{id}/status`

### 목록 뷰 (`/projects/:key/list`) (§9.5)
- **모드 토글(우상단)**: ① 전체 목록(표) ⇄ ② 분할 화면.
- **표 모드**: 사용자 지정 컬럼/정렬, 인라인 상태·담당자 변경, 퀵필터.
- **분할 모드**: 좌측 항목 리스트 + 우측 업무 상세 패널(§9.3 구조 그대로). 리스트 클릭 시 우측 즉시 갱신 → 페이지 이동 없이 연속 처리.
- API: `GET /work-items`, `GET /work-items/{id}`, `PATCH /work-items/{id}`

### 타임라인 (`/projects/:key/timeline`) (P2 — 구현)
- **로드맵 막대**: start_date~due_date 기간을 가로 시간축 막대로. 한 항목 = 한 행. 막대 좌우 위치/길이는 표시 구간(전체 항목의 min(start)~max(due)) 대비 비율로 계산.
- **행 구성**: 좌측 고정 라벨(TypeBadge + key + title) + 우측 트랙(막대 1개). 막대 색은 상태 신호용(StatusBadge 톤 재사용 — 색 남발 금지). 막대 위 진행률(progress) 채움 표시.
- **시간축 헤더**: 표시 구간을 월 단위 눈금으로(상단 고정). 항목은 start_date 오름차순 정렬.
- **일정 없는 항목**: start_date·due_date가 모두 없는 항목은 타임라인에서 제외(BE가 일정 있는 항목만 반환). 한쪽만 있으면 그날 점/짧은 막대로 표기.
- **로딩**: 행 골격 Skeleton(좌측 라벨 폭 + 우측 트랙). **빈 상태**: 공통 EmptyState("일정이 설정된 항목이 없습니다").
- **인터랙션(Phase1 범위)**: 막대/라벨 클릭 → 업무 상세(`/work-items/:key`). 드래그 리사이즈·의존선은 범위 밖(후속).
- API: `GET /projects/{id}/timeline` → `{ projectId, items: TimelineItem[] }` (TimelineItem: id·key·title·issueType·commonStatus·priority·assigneeId·epicId·startDate·dueDate·progress)

### 캘린더 (`/projects/:key/calendar`) (P2 — 구현)
- **월별 그리드**: 7열(일~토) × 주 행. due_date 기준으로 항목을 해당 날짜 칸에 배치(BE가 due_date별 묶음 반환).
- **상단 바**: ‹ 이전달 · "YYYY년 M월" · 다음달 › 네비(ds-ui Button `ghost`, 네이티브 위젯 금지) + "오늘" 버튼. 오늘 날짜 칸 강조(중립 톤 테두리).
- **날짜 칸**: 날짜 숫자 + 그날 항목 칩(TypeBadge 소형 + title 축약). 칸당 표시 한도 초과 시 "+N건" 더보기. 칩 클릭 → 업무 상세.
- **월 이동**: `year`/`month` state로 `GET ?year=&month=` 재호출. 미지정 시 현재 월(BE 기본값).
- **로딩**: 그리드 칸 Skeleton. **빈 상태**: 칸은 그리되 항목 없으면 비움(별도 EmptyState 불필요 — 달력 골격 자체가 맥락).
- API: `GET /projects/{id}/calendar?year=&month=` → `{ projectId, year, month, days: [{ date, items: TimelineItem[] }] }`

### 보고서 (`/projects/:key/reports`)
- **차트/표(P1)**: 진행률 · 지연 · 막힘 · 담당자 부하 · 분포 위젯(상태별/유형별/담당자별 work item 수) · 처리량(운영형).
- **P2 후보**: 번다운/번업·벨로시티(WMP-AGL-006) · **리드타임/사이클타임**(생성~완료 / 작업시작~완료 — 막힘·정체 발견과 직결, §9.2. measure_unit "리드타임" 시드와 연결) · 누적 흐름(CFD).
- **범위 밖(의도적 제외)**: **배포 빈도 등 CI/CD·릴리스 파이프라인 지표는 WorkMap이 추적하지 않는다.** 개발 통제·배포는 FlowGuard 축(CLAUDE.md §15.3 "관리·계획=WorkMap / 개발 통제=FlowGuard, 섞지 않음"). Jira 갤러리에 "배포 빈도 보고서"가 있어도 도입하지 않는다.
- API: `GET /projects/{id}/report`, `GET /projects/{id}/throughput`

### 승인 (`/projects/:key/approvals`)
운영형 워크플로 게이트 처리 화면. 승인 게이트(`is_approval`) 상태에 도달한 항목의 승인을 모아서 처리.
- **토글(우상단)**: 승인 대기 중 / 내가 요청 / 모든 승인.
- **표**: 업무 항목 · 상태 · 담당자 · 승인자 · 작업(승인/거부 버튼). 행 클릭 → 업무 상세.
- **빈 상태**: 승인 설정이 없을 때 안내("승인 설정"). 승인 설정(⚙)은 워크플로 편집기(`/admin/workflows`)로 연결.
- API: `GET /projects/{key}/approvals`, `POST /approvals/{id}/decision`

### 업무 상세 (`/work-items/:key`) (§9.3 — 핵심)
유형별 본문 + 우측 접이식 패널 + 상단 액션 바. 진입 형태(분할뷰/모달/딥링크) 무관 동일 구조.

**상단 바**
- 업무 key(예: ZGOH-2) · 위/아래 화살표(목록 내 이전/다음 이동) · 워치(👁 구독+구독자 수) · 공유 · `+ 액션 메뉴` · 구성(⚙).
- `+ 액션 메뉴`: 하위작업 추가 · 업무 연결 · 첨부 · 웹링크 · 추천 첨부 · 메뉴 검색.
- 구성(⚙): 이 화면에 보일 필드 설정 바로가기(필드 스킴, `/admin/field-schemes` 연계).
- 제목 인라인 편집. 만듦/업데이트 시각 표시.

**본문 (유형별 분기)**
- 공통: 설명(리치 텍스트) · 하위 작업 · **연결된 업무 항목** · 관련 문서(임베드) · 첨부/웹링크 · 댓글(@멘션).
- **Epic**: 하위 Story/Task/Bug 묶음 + 진행률 집계.
- **Story**: 인수조건 + 하위 작업.
- **Task**: 작업 체크리스트 + 공수(예상/실제) + 하위 작업.
- **Bug**: 재현절차 / 기대 vs 실제 / 환경 / 심각도.
- **Sub-task**: 부모 링크 + 단순 정보.
- ⚠️ **하위 작업 ≠ 연결된 업무 항목** (별개 섹션):
  - 하위 작업 = 부모-자식 계층(진행률 집계 대상).
  - 연결된 업무 항목 = 계층 무관 링크(blocks / blocked by / relates to / duplicates).

**승인 대기 영역 (게이트 진입 시)**
- 항목이 승인 게이트(`is_approval`) 상태이고 승인 PENDING이면, 본문 상단에 승인 대기 배너 표시(요청자·요청 시각·대상 다음 상태).
- 지정 승인자에게는 **승인/거부 버튼 + 코멘트 입력** 노출(비승인자에게는 읽기 전용). 처리 시 `POST /approvals/{id}/decision`.

**우측 패널 (접이식 섹션 — 한 덩어리 아님)**
- ▾ **세부 사항**: 담당자 · 레이블 · 상위 · Team · 기한 · 시작일 · Sprint · Story point · 보고자 · (측정: 단위·목표·현재값).
- ▾ **개발 (Git 연동)**: 커밋/브랜치/PR 연결 (P2).
- ▾ **자동화**: 규칙 실행 이력 (P2).

- API: `GET /work-items/{id}`, `PATCH /work-items/{id}`, `/status`, `/assignee`, `/measure`, `/convert`, `POST /work-items/{id}/subtasks`, `/comments`, `/attachments`, `/links`, `GET /work-items/{id}/activities`, `/approvals`, `POST /approvals/{id}/decision`

### 업무 만들기 모달 (전역 오버레이, §9.4)
> **만들기는 가볍게, 상세는 풍부하게.** 유형이 뭐든 동일한 모달 하나, 제목만 "에픽 만들기/스토리 만들기"로 바뀜.
- **필수**: 스페이스(프로젝트) · 업무 유형 · 요약. 상태(초기값=워크플로 시작 상태).
- **기본**: 설명(리치 에디터 — 굵게/리스트/이미지/코드/이모지/링크/실행취소).
- **선택**: 담당자 · 우선순위 · 라벨 · Epic 연결. (필드 설정 시 Bug 심각도 / Story 포인트 노출)
- 유형별 풍부한 필드(인수조건/재현절차/체크리스트/공수/측정)는 **모달에 없음** — 만든 뒤 상세에서 채움(§8.3a).
- `[ ] 다른 항목 만들기` 체크 → 연속 생성(모달 유지).
- 진입: 헤더 `[만들기]` · 각 영역 `+ 만들기`(인라인).
- API: `POST /work-items` (key 자동 발급)

### 관리자 마스터 (`/admin/*`)
- **측정 단위**(`/admin/measure-units`): name·valueType(NUMBER/BOOLEAN/SELECT)·suffix·options·isSystem. `GET·POST·PUT·DELETE /admin/measure-units`
- **필드 스킴**(`/admin/field-schemes`): 유형/프로젝트별 필드 표시 on/off. `…/admin/field-schemes`
- **워크플로 편집기**(`/admin/workflows`): 상태 목록 + 전이 화이트리스트(BIZ-010). `/admin/workflows`, `…/{id}/statuses`, `…/{id}/transitions`
- **업무 유형**(`/admin/issue-types`, P2): 5종 기본 삭제 불가. `…/admin/issue-types`
- **양식 빌더**(`/admin/forms`, P2): 양식 CRUD. `…/admin/forms`
- 공통: 마스터 데이터로 관리(하드코딩 금지), `is_system=true`는 삭제 불가.

### UI 공통 규칙 (구현 강제 — 상세는 CLAUDE.md FE 아키텍처 규칙)
- **ds-ui 필수, 네이티브 UI 금지**: `alert/confirm/prompt`·네이티브 `<select>/<checkbox>/<date>/<dialog>` 금지 → ds-ui Dialog/Select/Checkbox/DatePicker/Switch/Toast로 대체.
- **색 절제**: 신호(상태·우선순위·막힘)에만 색, 본문/레이아웃은 중립 톤. 알록달록 금지, Tailwind 테마 토큰만.
- **버튼 일관성**: 생성/추가/저장=primary · 수정=secondary · 삭제=destructive · 취소=ghost. 같은 액션은 전 화면 동일 색·위치·아이콘. 공통 래퍼/상수로 관리.
- **반복 패턴 일관성(공통 컴포넌트 1개로 재사용)**: 경고/정보/성공/에러(Alert/Toast — 의미별 색·아이콘 고정) · 검색(SearchInput) · 필터(FilterBar/QuickFilterBar) · 빈 상태(EmptyState) · 확인삭제(ConfirmDialog) · 폼 필드(Field 래퍼) · 페이징/테이블(ds-ui Pagination/Table). 화면마다 제각각 만들지 말 것.
- **로딩=스켈레톤**: 위 "공통 UX 규약 — 로딩 스켈레톤" 참조.

## 공통 UX 규약 — 로딩 스켈레톤 (전 화면 횡단)

> 데이터 패칭(TanStack Query) 동안 빈 화면/스피너 대신 **스켈레톤**(회색 placeholder)을 표시한다. Jira 동일 패턴. 횡단 관심사이므로 화면 기능별이 아니라 공통 규약으로 둔다.

**원칙**
- 서버 데이터를 불러오는 **모든 화면/영역**에 스켈레톤 적용. 로딩 상태(`isLoading`/`isPending`)에서 실제 콘텐츠와 **같은 레이아웃 골격**을 회색으로 그린다(레이아웃 시프트 최소화).
- ds-ui `Skeleton` 컴포넌트를 **우선 사용**. 화면별 조합은 자체 래퍼로 구성.
- 스피너는 **버튼/인라인 액션 등 작은 부분 로딩**에만. 페이지/리스트/카드 단위 로딩은 스켈레톤.
- 첫 로딩 = 스켈레톤. 재패칭(이미 데이터 있음) = 기존 데이터 유지 + 미묘한 로딩 표시(placeholderData/keepPreviousData).

**적용 대상 (화면별 스켈레톤 형태)**
| 화면/영역 | 스켈레톤 형태 |
|-----------|--------------|
| 회사 홈 | 지표 카드 N개 + 막힘/지연 목록 행 placeholder |
| 목록 뷰(표/분할) | 표 헤더 + 행 8~10개 회색 바. 분할 우측은 상세 골격 |
| 보드 | 컬럼별 카드 3~4개 placeholder |
| 백로그 | 스프린트 헤더 + Epic 트리 행 placeholder |
| 업무 상세 | 제목/본문 블록 + 우측 패널 필드 행 placeholder |
| 프로젝트 목록 | 카드/행 placeholder |
| 받은함·검색·보고서 | 리스트 행 placeholder |
| 관리자 마스터 | 표 행 placeholder |

> 구현 시 각 화면의 query 로딩 분기에서 해당 스켈레톤 컴포넌트를 렌더. 공통 프리미티브(SkeletonText/SkeletonRow/SkeletonCard)는 ds-ui Skeleton으로 조립.
