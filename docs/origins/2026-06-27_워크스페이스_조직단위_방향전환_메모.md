# 워크스페이스 = 조직(본부/팀) 단위 방향 — 입력 메모

> 기록일: 2026-06-27 | 출처: FE 미연결 4종 E2E 점검 중 사용자와의 대화
> 성격: **제품 방향 입력(원본)**. 정제하지 않고 보관. 아직 설계 캐스케이드 미반영 — 다음 세션에 T1→T3 설계로 풀 것.
> 처리 결정(사용자, 2026-06-27): "방향만 기록, 다음에 설계." 지금은 구현/화면 신설 착수하지 않는다.

---

## 1. 발단 (E2E 화면 관찰)

- `/projects` 진입 시 워크스페이스가 **1급 화면 없이** 프로젝트 목록의 "필터 드롭다운(전체 워크스페이스) + [워크스페이스 만들기] 버튼"으로만 존재.
- 사용자 위화감: "진입하자마자 프로젝트인데, 워크스페이스는 어느 단계에서 진입하나?" → "좀 이상하지 않나?" → "슬랙도 그렇고, 지라도 워크스페이스가 있지 않나?"

## 2. 현재 설계가 그렇게 된 근거 (실측)

- **T1-1 §WMP-WS-001 제약**: "Owner/Admin만 생성. **Phase 1은 단일~소수 워크스페이스 전제.**" → 의도적으로 워크스페이스 전용 화면을 안 둠.
- **T3-3 IA**: 글로벌 LNB에 회사홈·받은함·검색·프로젝트·설정만. **워크스페이스 메뉴 항목 자체가 없음.** 워크스페이스는 `/projects`의 필터 + 생성으로만 등장(§59, §111).
- 즉 현재 화면은 설계대로 동작(버그 아님). Jira도 일하는 화면은 project 중심이라, "프로젝트를 1급으로" 둔 건 Jira와 같은 결.

## 3. 타 제품 비교 (검증)

| 제품 | "워크스페이스/스페이스"가 가리키는 것 | 1급 화면? |
|---|---|---|
| Slack | 계정·조직 전체(채널·사람이 다 그 안). 벗어나면 아무것도 없음 | 그렇다 — 곧 앱 전체 |
| Jira | 프로젝트 위 컨테이너="space", 그 위에 org→site. 일상 동선 주인공은 project | 부분적(관리 레이어). 일하는 화면은 project |
| WorkMap(현재) | "프로젝트를 담는 묶음", Phase1 소수 전제 | 아니오(필터+생성) |

→ "타 제품에 워크스페이스가 있다"는 맞지만, 그것이 곧 "1급 메뉴여야 한다"의 근거는 아님. 단어가 같아도 계층 위치가 다름.

## 4. 사용자 핵심 발언 (방향)

> **"워크스페이스는 결국 운영팀, 개발팀 등 본부, 등 조직이 될 확률도 크고"**

- 워크스페이스를 **조직 단위(본부/팀)**로 본다 → Phase1 "단일~소수 전제"와 어긋남. 본부 단위면 자연히 5개+ 로 늘어남.

## 5. 조직 단위로 가면 따라오는 설계 이슈 (다음 세션 검토 목록)

1. **워크스페이스 1급 승격**: LNB 메뉴 또는 `/projects` 상단에 워크스페이스 목록/카드. 자기 화면(목록·상세·소속 프로젝트·멤버) 필요.
2. **워크스페이스 단위 경계**: 현재 가시성은 *프로젝트* 단위(WMP-WS-006)뿐. 조직이면 *워크스페이스* 단위 멤버십·가시성 경계 필요(예: 운영팀 WS를 개발팀이 못 봄). → BIZ-108(가시성) 재설계 영향.
3. **권한 모델**: 워크스페이스별 Owner/Admin? 전사 Admin vs 워크스페이스 Admin 구분?
4. **수정 진입 비대칭(별개·작은 건)**: 현재 생성은 헤더 고정, 수정은 필터에서 WS 선택해야 발견. 설계 위배는 아니나 UX 비대칭 — 1급 승격 설계 시 자연 흡수되거나, 그 전 작은 수정으로 처리 가능.

## 6. 미결 질문 (설계 착수 전 사용자 확정 필요)

- 워크스페이스 규모: 전사 1~2개 vs 본부별 5개+ (방향상 후자로 기울지만 명시 확정 필요)
- 워크스페이스가 권한·가시성 경계를 갖는가, 아니면 단순 분류 묶음인가
- 조직도(본부>팀) 같은 계층이 워크스페이스 안에 또 필요한가, 워크스페이스=팀 1레벨인가

## 7. 지금 당장 하지 않는 것 (결정)

- 워크스페이스 화면 신설·LNB 메뉴 추가·권한 재설계 **착수 안 함**.
- 현재 4종(WI-001/WS-001/WS-004/WS-006) FE 연결은 그대로 두고 E2E 마무리.
- 본 방향은 **CR 대상**(Phase1 설계 전환) — 착수 시 T1(요구·BIZ·POL)→T3(API·화면) 캐스케이드 + CR 부여.
